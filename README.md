# Baumayer Bot

Telegram-бот для управления строительными проектами, заявками и сотрудниками. Пользователи работают с профилем, проектами, заявками на выполнение работ и балансом, а администраторы управляют доступом, сотрудниками и их ролями.

> Проект находится в разработке. Часть кнопок пользовательского интерфейса пока является заготовкой, а API-модуль ещё не реализован.

## Возможности

- регистрация пользователей по Telegram ID;
- автоматическое назначение роли администратора пользователям из `SUPERADMIN_IDS`;
- профили пользователей с ФИО, адресом объекта, банком и расчётным счётом ИП;
- проекты строительства:
  - создание проекта администратором;
  - просмотр проектов, в которых пользователь является участником;
  - хранение участников проекта и их ролей;
- заявки на работы:
  - создание заявки с категорией, названием и описанием;
  - просмотр собственных заявок;
  - обработка заявок менеджерами;
  - отклики исполнителей;
  - статусы `new`, `in_progress`, `done`, `rejected`, `cancelled`, `disputed`;
  - уведомления клиентов, менеджеров и исполнителей в Telegram;
- управление сотрудниками и ролями через админ-панель;
- кошельки пользователей и проекты транзакций с поддержкой пополнения, списания и заморозки средств.

## Технологический стек

- Python 3.12;
- [aiogram 3.15](https://docs.aiogram.dev/) — Telegram Bot API;
- [SQLAlchemy 2](https://www.sqlalchemy.org/) в асинхронном режиме;
- PostgreSQL 16 через `asyncpg`;
- Redis 7 — подготовлен в Docker Compose для фоновой инфраструктуры;
- FastAPI и Uvicorn — заготовка отдельного API-сервиса;
- Docker и Docker Compose.

## Как это работает

При запуске `bot/main.py` приложение инициализирует таблицы PostgreSQL, создаёт экземпляр бота и запускает polling через aiogram. `UserMiddleware` регистрирует Telegram-пользователя или обновляет его данные до передачи события обработчикам.

Обработчики в `bot/handlers/` вызывают сервисы из `bot/services/`, а сервисы работают с моделями SQLAlchemy и асинхронными сессиями из `bot/database.py`. Например, заявка создаётся через `create_order`, после чего менеджеры получают уведомление; менеджер меняет статус заявки, а исполнители могут отправлять отклики.

## Запуск через Docker Compose

### 1. Подготовьте конфигурацию

```bash
cp .env.example .env
```

Заполните в `.env` как минимум:

- `BOT_TOKEN` — токен Telegram-бота;
- `SUPERADMIN_IDS` — Telegram ID супер-администраторов через запятую;
- `DB_USER`, `DB_PASSWORD`, `DB_NAME` — параметры PostgreSQL.

В Compose имена `DB_HOST=postgres` и `REDIS_HOST=redis` соответствуют именам сервисов и обычно должны оставаться без изменений.

### 2. Запустите сервисы

```bash
docker compose up --build -d
```

Логи бота:

```bash
docker compose logs -f bot
```

Логи всех сервисов:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `pgdata`.

## Локальный запуск бота

Для локального запуска нужен доступный PostgreSQL и установленные зависимости бота:

```bash
cd bot
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python main.py
```

В локальном `.env` укажите `DB_HOST=localhost`, если PostgreSQL запущен на машине разработчика. Обязателен `BOT_TOKEN`.

## Основные команды Telegram

- `/start` — открыть главное меню;
- `/profile` — открыть профиль;
- `/orders` — открыть раздел заявок;
- `/myproject` — открыть проекты пользователя;
- `/newproject` — создать проект (только администратор);
- `/admin` — открыть админ-панель (только администратор).

## Модель ролей

Системные роли пользователя включают `pending`, `admin`, `staff` и пользовательские роли, например `foreman`, `engineer` и `worker`. Для сотрудников дополнительно используются роли подразделений:

- менеджер (`manager`) со сферой `order`, `material` или `emergency`;
- исполнитель (`executor`) со сферой `builder`, `foreman`, `laborer` или `buyer`.

Пользователь впервые получает роль `admin`, если его Telegram ID указан в `SUPERADMIN_IDS`; остальные новые пользователи создаются со статусом `pending`.

## Важные замечания

- `api/main.py` сейчас пуст, поэтому API-контейнер не предоставляет реализованных endpoint'ов.
- Таблицы создаются при старте бота через `Base.metadata.create_all`; каталог миграций Alembic в репозитории отсутствует.
- Кнопки «Смета», «Выполнение работ», «Архитектор», «Дизайнер», «Настройки» и «Статистика» присутствуют как элементы интерфейса, но соответствующая функциональность ещё не реализована полностью.
- В `wallet.py` запрос выплаты пока только отправляет пользователю подтверждающее сообщение; уведомление администратора отмечено как будущая задача.
- Redis подключён в Compose и конфигурации, но в текущем коде бота отдельное использование Redis не показано.
